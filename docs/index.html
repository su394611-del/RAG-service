01 / Capabilities

Inside the retrieval stack.

The repository combines model-backed vector search, tenant-context handling, defensive examples and observability into a cohesive Python workflow.

Six implementation areas
⌕01 / VECTOR SEARCH

Semantic embeddings

Encode text with BAAI/bge-small-en-v1.5 through Sentence Transformers; query a Qdrant collection using cosine similarity to retrieve relevant passages.

◇02 / TENANCY

Tenant-filtered retrieval

Attach a tenant_id payload filter to vector search so the example knowledge bases for tenant_a and tenant_b remain separated by retrieval context.

↺03 / CACHING

Semantic caching + TTL

Reuse similar results based on cosine similarity while distinguishing tenants, sessions and top_k; the cache is process-local and expires records by time.

▣04 / API

FastAPI interface

Expose a local query endpoint with bearer-token checks, health status, tenant cache statistics and optional protected metrics. Request throttling is included as a demo control.

◈05 / SAFEGUARDS

Input handling patterns

Explore regex-based PII redaction and heuristic prompt-injection flags. These are intentionally limited examples, not complete security defenses.

▥06 / DEVELOPER WORKFLOW

Diagnostics + notebooks

Run dependency diagnostics, offline self-tests, real retrieval demos and a Jupyter notebook walkthrough. CPU mode works without a CUDA GPU.

03 / Engineering details

Built for reproducible exploration.

The workflow separates retrieval behavior, simple defenses and operational instrumentation so each can be inspected directly in code.

Retrieval and isolation

Core algorithmic and data-layer ideas in the repository.

  • Vector representation with BAAI/bge-small-en-v1.5
  • Qdrant payload conditions based on tenant_id
  • Cosine-similarity nearest-neighbor passage search
  • Tenant and session scope in the process-memory cache
  • Cache expiration using a time-to-live policy
  • Optional local Qdrant persistence through QDRANT_PATH

API and observability

Operational concepts for local experimentation.

  • FastAPI routes for query, health and cache statistics
  • Per-tenant bearer tokens read from environment variables
  • Client-IP rate limiting in the demonstration
  • Request count, error, latency and cache-hit metrics
  • Optional process-memory metrics
  • Offline checks of isolation, caching and validation behavior

05 / Getting started

Run it locally.

Clone the repository, install dependencies, check the environment, and run either an offline test or the model-backed demonstration. The first real demo downloads embedding model weights.

Windows PowerShell
POWERSHELL / LOCAL SETUP
git clone https://github.com/su394611-del/RAG-service.git
cd RAG-service

py -3.12 -m venv .venv-rag
.\.venv-rag\Scripts\python.exe -m pip install -U pip
.\.venv-rag\Scripts\python.exe -m pip install -r requirements.txt

# Inspect installed packages; no model download
.\.venv-rag\Scripts\python.exe RAG_Service_Corrected_2026_Diagnostics.py --doctor

# Exercise offline validation checks
.\.venv-rag\Scripts\python.exe RAG_Service_Corrected_2026_Diagnostics.py --self-test

# Load embeddings and run tenant-scoped queries
.\.venv-rag\Scripts\python.exe RAG_Service_Corrected_2026_Diagnostics.py --demo

Three ways to explore

  1. Diagnostics: check available dependencies and accelerator support.
  2. Self-test: exercise isolation and validation without downloading the model.
  3. Retrieval demo: initialize BGE embeddings and Qdrant, then retrieve fictional sample passages.

For the REST API, configure private tenant tokens through environment variables and start --api. See the README for setup, sample requests and safety notes.

Scope and engineering boundaries

This is a retrieval and extractive-answering demonstration. It does not generate new answers with a language model. Tenant filtering, token handling, regex PII checks, pattern-based injection checks, rate limiting and process-local caching illustrate engineering patterns; they are not a substitute for penetration testing, formal isolation assurance, production load testing or a full security assessment. Never deploy the example API to a public network without independent review.

08 / Common questions

Questions before running.

Does this application generate LLM responses?

No. The currently documented response path returns knowledge-base excerpts, using embeddings to find relevant passages. The name describes a RAG-oriented retrieval component, not a full generative pipeline.

Do I need a GPU?

No. The embedding model and retrieval can run on CPU. A compatible CUDA-enabled NVIDIA GPU and PyTorch installation are optional for embeddings.

How are the two sample tenants separated?

Qdrant payload filters select records for the authorized tenant context. Cache entries are also scoped by tenant and session. These examples should not be treated as formal production security validation.

Does it connect to a production data source?

The included demonstration uses fictional subscription and product documents. They do not represent verified information about a real company, and the metrics are local demo observations rather than measured production benchmarks.
